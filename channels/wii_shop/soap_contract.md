# Offline CAS ListTitles contract

Reviewed October 25, 2026. This is a bounded, read-only **codec component**, not
a running commerce service. No route imports it. It does not establish that the
installed Japanese Shop v21 uses this library revision or invokes this operation
from its original storefront pages.

The later [retail commerce-surface audit](../../research/wii_shop_commerce_surface_20261025.json)
found concrete v21 fields absent from this older source implementation:
`AttributeFiltersEx` and `OrderByAttribute`, with additional typed subfields.
Their enum meanings and storefront use are unresolved. This codec is therefore
an incomplete v21 contract and remains offline; accepting its older subset is
not evidence of retail service compatibility.

The [metadata-only source report](../../research/wii_shop_soap_contract_20261025.json)
records five private client-library files verified against their extraction
inventory. That verification establishes extraction consistency, not independent
Nintendo provenance or an exact retail executable match. Recovered source bodies
remain outside Git. No original software was compiled or executed for this work.

## Source-backed request shape

The recovered `ec_listTitles.h:82` defaults to `ListTitles`; its `.cpp:167-210`
builds a CAS request. `ec_soap.cpp:25-139` establishes SOAP 1.1, namespace
`urn:cas.wsapi.broadon.com`, `SOAPAction`
`urn:cas.wsapi.broadon.com/ListTitles` and operation `cas:ListTitles` with
`xsi:type="cas:ListTitlesRequestType"`.

The constructor in `ec_soap.h:233` sets **Version 2.0**. A nearby older comment
in the listing source says 1.0; the implemented constructor governs this codec.
This is a library finding, not a statement of the installed retail version.

| Fields | Evidence and codec behavior |
| --- | --- |
| `Version`, `MessageId`, `Region`, `Country`, `Language` | Emitted by the common builder; required structurally |
| `DeviceId`, `DeviceToken`, `AccountId`, `ApplicationId`, `TIN`, `Age` | Conditional common fields; retained as opaque strings, never authenticated |
| `ListResultOffset`, `ListResultLimit` | Unsigned 32-bit caller values, including zero; no invented page-size mapping |
| repeated `Attributes` | Requested attribute-name strings, preserving duplicates and order |
| repeated `AttributeFilters` | Each contains `Name` then `Value`; preserves API-first/application-second source ordering without inferring which produced a filter |
| repeated `TitleId` | Exactly 16 hexadecimal digits; canonicalized to lowercase, preserving duplicates and order |

The parser accepts arbitrary namespace prefixes and a quoted or unquoted
SOAPAction. Unknown fields, wrong namespaces/actions/types, duplicate singleton
fields, multiple operations, SOAP headers and mixed content are rejected. These
strict exclusions are this component's scope; they are not a recovered WSDL.
The original builder emits the request type; the parser also accepts its absence
because dispatch is based on the expanded operation name, never a type annotation.

Local defensive bounds are 128 KiB XML, 2,048 elements, depth five, 256 instances
of each repeated field and 4,096 characters per scalar. They are implementation
bounds, not native protocol limits. UTF-8 input is decoded before parsing; DTDs
and entity declarations are rejected. No request values appear in parser errors.
Common account/device data is excluded from object repr; callers must continue
to keep returned common fields private. No device/account files are read.

## Source-backed response subset

The generic response reader in `ec_soap.cpp:294-349` is lexically sensitive. It
looks for `soapenv:Envelope`, `soapenv:Body`, then unprefixed
`ListTitlesResponse` with the exact sole attribute
`xmlns="urn:cas.wsapi.broadon.com"`. Equivalent namespace prefixes generated by
a generic XML serializer are therefore insufficient evidence of compatibility.
The codec deliberately emits those literal forms, an XML declaration and full
opening/closing tags. It does not echo account IDs, device IDs, tokens or message
IDs: the reviewed common response reader does not require those fields.

The optional `TimeStamp` precedes required `ErrorCode`. The codec requires an
explicit `error_code="0"` for an **offline fixture only**. It has no error/fault
serializer or live success handler. It never derives timestamps or simulates
account state. `ListResultTotalSize` is caller supplied. The title-list reader
(`ec_listTitles.cpp:220-253`) requires it and consumes repeated `Titles`.

`ec_soap.cpp:1129-1240` requires `TitleId` per title and permits absent Contents,
Attributes, Ratings and Prices in the generic parser. The codec implements only
`TitleId` and optional repeated `Attributes/Name/Value`, whose shape is established
by `ec_soap.cpp:937-1010`. The caller must supply a nonempty source reference for
the total, every title ID and every native attribute name/value mapping. References
are deliberately omitted from the wire. They are caller assertions; this module
does not validate a source's provenance or truth. There are no default attribute
names and no implicit mapping from third-party catalog fields.

ID-only items are useful parser fixtures. They do not establish useful original
Shop rendering. Historical points are not sufficient for `Prices`: the reviewed
pricing parser also expects fields such as `ItemId`, `Price`, `LicenseKind` and
limits. The codec consequently has no pricing, rating, ownership, availability,
entitlement, purchase, ticket, TMD, content or installation serializer.

## Integration gates and verification

`EC_ListTitles` checks initialization, confirmed device key pair, successful
connection and a nonempty account (`ec_listTitles.cpp:293-304`). Accepting XML
does not satisfy those prerequisites. A future service must establish the
authorized account/device contract; fabrication or bypass is not an integration
option. Native JavaScript `getTitleInfos` enumerates owned ES titles; this codec
must never feed the imported catalog to that interface.

Before any route enables this component, verify the retail call path and request
version, original page/script flow, origin and transport requirements, real
native attribute names and meanings, authorized identity handling and a response
capture or matched-client parser test. Independently establish catalog data
authority and filtering semantics. The parser records filters; it does not claim
to evaluate them. Historical catalog IDs remain source-reported, not TMD verified.

Fifteen synthetic tests exercise repeated fields, Unicode/XML escaping, common
field privacy, namespace/action/type isolation, malformed/hostile XML and local
bounds, uint32 ranges, exact response lexical forms, explicit empty pages and
rejection of missing evidence. The response byte bound is enforced incrementally
after escaping and UTF-8 encoding each line, before extending its output buffer;
an oversized multi-title fixture verifies that later attributes/titles are never
processed. Fixtures use clearly synthetic values and no real
device/account material. They validate the implemented subset and reviewed
reader contract; no original-client execution, server or browser integration is
claimed.
