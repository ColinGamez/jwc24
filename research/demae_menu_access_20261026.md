# Demae current-menu data boundary

October 26, 2026. This targeted read-only check followed one existing branch
observation; it was not a scrape/import, ordering attempt or delivery-coverage
check. No owner address, account, cookie or API credential was used. No catalog
or source timestamp changed.

The retained observation names provider branch 3138402 and its
[official restaurant page](https://demae-can.com/shop/menu/3138402). The indexed
rendered view exposed dish names/prices and descriptions mentioning choices,
but no verified tuple of provider variant ID, option label, variant price and
variant-specific stock. The view's destination-not-set and outside-reception
messages do not establish a product's stock or delivery eligibility. Indexed
page freshness does not independently establish current branch availability.
No product-detail API endpoint or contract was inferred from this page.

The investigator checked the [consumer terms](https://demae-can.com/navigate/termsofuse)
and reported Article 14's personal/private-use boundary and Article 15's content
rights. Root's later direct read returned 403, so this report does not claim a
successful direct re-fetch or bypass that response. Personal-use provisions
must not be flattened into either a universal prohibition or a general JWC24
redistribution license; the intended service's scope still needs confirmation.

The [official API-document terms](https://terms2.line.me/demae_dev_terms?lang=ja)
were directly readable. They limit document use to contracted service users,
restrict it to the agreed service purpose and do not grant ownership or broad
reuse rights over documentation/data. They do not establish that JWC24 has
an API agreement, credentials or a currently usable public menu feed.

The actionable input remains an authorized provider/merchant specification and
actual branch-specific export or delivery: stable parent/variant identities,
option labels, real individual prices, observed stock, dates, and supported
ordering/handoff identity. The existing Hot Pepper directory remains a separate
restaurant-discovery source; its directory records are not orderable menus.

No standard-size row, copied parent price, guessed stock, fake identifier or
new orderable restaurant was created. The new native item/model checks remain
useful transport/model components, with their current-data gate still open.
